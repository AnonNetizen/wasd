# 代码文档规范

> **权威范围**：本文件定义长期代码模块文档应记录的公共契约，以及何时无需更新文档。

## 1. 何时更新

只在以下任一项变化时更新对应 `docs/代码/<module_id>.md`：

- 公共 API、signal、输入输出或生命周期。
- 玩家或其他模块可观察的行为。
- 模块所有权、上游 / 下游依赖或禁止依赖。
- 公开数据 schema、存档 / 回放 wire 或错误处理契约。
- 稳定扩展点或测试入口。

以下变化默认不更新文档：

- 提取、合并或重命名私有 helper。
- 只改变内部文件布局、局部算法或测试实现。
- 新增测试 case 而测试政策和公共行为不变。
- 格式化、注释、类型补强和无行为 bugfix。

新增私有脚本仍由现有模块文档覆盖，不为每个文件建立文档。若变化同时触及 GDD、数据手册、locale、词表或测试政策，按 `docs/AI协作/文档维护指南.md` 只更新相应直接权威。

## 2. 模块文档最小内容

| 内容 | 要求 |
|------|------|
| 职责 | 负责什么、不负责什么 |
| 公共契约 | API、signal、输入输出、生命周期、失败语义 |
| 数据 / wire | schema、单位、版本、兼容或拒绝策略 |
| 依赖 | 上游、下游、禁止依赖、autoload 边界 |
| 扩展点 | 新内容或新行为应该从哪里接入 |
| 测试入口 | 相关单测 / smoke / replay 命令及何时运行 |
| 人工验收 | 仅在确有视觉、听觉、手感或真实设备要求时列出 |

私有文件清单、逐函数说明、逐测试 case、最近通过数量、提交历史和完整验证日志不属于模块文档。

## 3. 文件头引用

长期维护脚本使用：

```gdscript
# Doc: docs/代码/<module_id>.md
```

多个私有 helper 可以共同指向父模块文档。自动生成文件、测试、一次性调试脚本和明显被父模块覆盖的极小 helper 可不写 `# Doc:`。

## 4. 建议模板

```markdown
# <ModuleName>

> **权威范围**：本文件记录 <ModuleName> 的公共代码契约。

## 职责
## 公共 API 与 signal
## 数据 / wire
## 依赖与扩展点
## 失败与兼容
## 测试入口
## 人工验收（如适用）
```

## 5. 收尾判断

- 公共契约未变：不改文档，并在交付说明中写明。
- 公共契约变化：只改所属模块文档；不要把相同内容复制到 AI 导航、测试策略、TODO 或 current state。
