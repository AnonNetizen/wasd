# 2026-08-06 会话日志

## ADR #187：开局护盾归零与超量护盾统一上限

- 用户要求护盾不再作为内置英雄的开局常驻机制，并把超量护盾上限改为生命上限与护盾上限之和。按现有普通护盾会在脱战后回复的语义，将两个内置主智能碎片的 `base_stats.max_shield` 一并设为 `0`，避免只清空当前值后又自动回满。
- Player 新增统一容量 `max_life + max_shield`：`add_overshield()` 只返回实际接纳量，调试设置、快照恢复和属性重建都会按容量钳制；HUD 的超量护盾条使用同一上限。局内通过属性修正获得 `max_shield` 时，仍按既有规则立即补充等量普通护盾。
- L1 覆盖两个内置主智能碎片的零基础护盾，以及 `100 max_life + 100 max_shield = 200` 的超量护盾容量、跨上限增量返回值和超限快照恢复钳制。contracts、数据 / schema、三档 lint、L1、runtime、save、Godot 4.7.1 headless boot 均通过；既有坏档负向诊断与 headless 退出提示保持预期。
- 四份 Replay v4 黄金回放均完成 runtime rerun，data fingerprint `e774ed3a86b7ef747c34105af52da9c21153e157debe3eed304f51b95a7359dc` 与 map hash `da44e2109c9dc3cb2868ec8367900a2570692ee4c36574e34305a50216a5c76a` 不变。Replay 摘要没有护盾字段，因此黄金文本不修改；Run v12、Replay v4、Meta v2、游戏 v1.11 与数据 schema 不升级。
- 事实型审查发现 HUD 的 `ProgressBar` 为渲染 0 护盾而使用的最大值占位 `1`，会在生命 / 语言刷新时被旧调用误当成真实最大护盾，使超量护盾条临时多 1 点容量；现改为单独保存真实防御值，并增加 L1 回归。修复后未发现仍未处理的 P0 / P1 / P2 问题，semantic advisory 无 warning。
- 同步 GDD v1.54、ADR、Gameplay Runtime、Combat、数据手册、测试策略、AI 导航 / 知识索引与三层项目记忆；长期记忆从 210 行自动瘦身，旧日条目改为月度聚合。
- 人工项保持待用户验收：两个内置主智能碎片进入正式对局时普通护盾为 0；局内获得护盾上限后普通护盾正确出现；超量护盾到达组合容量时不再增长且 HUD 上限可读。AI 未执行或代替这些人工验收。

## ADR #188：Gear Mod 纯局内化与 Roguelike 核心循环

- 用户确认正式定位改为“俯视角射击 Roguelike”，不再使用刷宝撤离、搜打撤、暂存战利品或带回结算；内部 `mode_standard_survival` id 保持稳定。
- `GearModSystem` 改为无状态规则服务；`GameplayRunLoop` 权威保存 `{mod_id: rank}`。每局空 Mod，首次为内部 rank 0、重复升至 rank 5，第七份及以后通过 `gear_mod_overflow` 转 75 局内金币。Player / WeaponSystem 使用替换式 Gear Mod modifier 层，Run 恢复在实体恢复后统一应用一次。
- 敌人、缓存和五类事件共用统一授予入口：追击者伤害 Mod 5%、喷吐者扩散 Mod 2.5%、壁垒者后坐 Mod 15%；持续事件固定一个普通 Mod，金币坛最多两个不重复 Mod，血坛无 Mod；Mod 缓存公共池独立两抽，资源缓存改即时金币。
- 删除标题 Gear Mod 入口、正式面板 / 行模板、库存 / loadout / capacity / drain / dust / 升级 / 分解 / fusion 与 Meta 写入；开发者测试岛只保留纯内存 Mod/rank 预览，外部 `ModLoader` 不变。
- 模块世界 schema v4 删除撤离槽 / 路线 / role / placement；默认模块世界与 open-warzone 都在意识核 `completes_run` 后立即结束。结果页显示最终本局构筑，不再显示带回 / 丢失。
- 版本升级为 Meta v3、Run v13、Replay v5、游戏 v1.12；Meta v2→v3 保留主 / 副碎片并删除旧 Gear Mod profile，不补偿；旧 Run v12 与 Replay v4 明确不兼容。
- `module_resource_cache` 与 `module_crossroads` 因奖励语义改变导致 gameplay hash 变化，被 baker 自动降为 `module_review_candidate`；AI 未重新批准，技术切片暂用 `module_flat_ground`，等待人工玩法复核。
- 自动验证覆盖 contracts、数据 / schema、三档 lint、module bake/editor、Gear Mod、runtime、world-event、save、loading、完整 / 技术模块世界、debug test arena、headless editor / boot、Replay v5 四条黄金回放和文档健康；按用户要求未运行性能 probe，也未以局长作为自动门槛。
- 事实型代码审查发现并修复四项实际问题：满阶溢出先改 rank 后发金币会在金币事务失败时破坏原子性；Run 恢复可静默接纳未知 / 越界 Mod；死亡 / 通关后只清字典而未立即替换实体 modifier 层；debug test arena 的自由技能可能先杀死后续断言目标。修复后相关 smoke、headless 与四条 Replay v5 runtime summary 全部复跑通过，未留下 P0 / P1 / P2 问题。
- 新增 `docs/reports/2026-08-06-health.md`：pre-commit 12 / 12、contracts / data / schema、三档 lint、文档 / 知识库与 4 / 4 黄金回放均为绿色；仓库尚无 `tools/health_metrics.py`，前三项精确比率只记录 lint 代理值，不伪造百分比。
- 待人工验收：标题页无局外 Mod 入口、局内掉落 / 升阶反馈、最终构筑结果页、中英文布局、意识核立即通关节奏，以及两个 candidate 奖励模块的玩法复核。

## ADR #189：默认开放内容解锁与标题图鉴

- 用户要求参考《以撒的结合》为英雄 / 智能碎片、Gear Mod、敌人增加横向解锁与图鉴；当前全部内容和未来未特别声明锁定规则的内容都默认开放，技能 / 被动随英雄整包，不恢复永久属性成长。
- 新增 `ContentUnlockSystem` autoload 与稀疏 `content_unlock_rules.json`。规则只支持生成契约登记的 `all` / `any`、结算局数、通关次数、指定英雄通关、总击杀和指定敌人击杀；DataLoader / Python 双端拒绝缺规则、闲置规则、非法 subject、锁定条件对象、技能独立锁定和初始内容池枯竭。
- Meta 升 v4，稀疏保存 `content_progression.unlocked/counters`，默认开放内容不落盘；Run 升 v14，保存稳定排序的 `content_availability` 与未结算 `content_progress_delta`；Replay 升 v6，保存同一快照并在播放时忽略本机 Meta；游戏版本升 v1.13。Meta v3 无损迁移，旧 Run v13 只删除 Run，旧 Replay v5 明确拒绝。
- `GameplayRunLoop` 在任何相关 RNG 消费前冻结英雄、Gear Mod、敌人池；模块 / 世界事件 / open-warzone 敌池和 Mod 公共池 / 掉落表都先求交。死亡 / 通关原子提交并返回本次新解锁，保存退出保留增量，放弃 / 重开丢弃；Replay、smoke 和开发者测试岛禁止长期提交。
- 标题在设置与退出之间新增图鉴，经 `UIManager` 管理；英雄、Gear Mod、敌人三分类支持即时双语刷新和焦点 / `ui_back`。锁定条目严格只显示 `???`、通用剪影、要求与数字进度，不查询或显示真实名称、图像、描述、属性；结算页只在非空时显示本次新解锁。
- 新增 `content-progression-smoke` 与 `codex-smoke`；同步 contracts、数据 / locale 手册、GDD v1.56、ADR、词表、DataLoader / Save / Replay / Gameplay / UI / 相关模块文档、测试策略、AI 导航 / 知识索引与三层项目记忆。模块世界 smoke 中两处旧 Run v13 断言在集成回归时升级为 v14。
- 四条黄金回放重录为 Replay v6，均携带 2 个英雄、3 个 Gear Mod、5 个敌人的冻结快照；运行时重放全部通过，最终 data fingerprint 为 `83d12d96aceaf0a50ef20f2d9b840433a176258c48d5d9f0a82e5f027d58f3fb`，map hash 保持 `40d2a0870aa54bc856fdf34002ed6d5dd406ad86be6bcefffd543ae35158552d`。
- 自动验证覆盖 contracts / data / schema、三档 lint 与回归、专项解锁 / 图鉴、Gear Mod、世界事件、完整 / 技术模块世界、runtime / save / loading / settings / UIManager、L1 / input / Replay input、Replay v6 格式与四条黄金回放、Godot 4.7.1 headless editor / boot、文档 / JSON 健康。按要求未运行性能 probe；Godot 退出期 RID / ObjectDB 日志与坏档 / 非法配置负向夹具为既有预期，不改变各 runner 的 PASS。
- 事实型代码审查发现并修复三组实际问题：敌人 CSV 空白 `default_unlocked` 在运行时 / Python 校验层会被误当成锁定，且 Python 仍错误要求技能必须显式填写该字段；保存 Run 的潜在新解锁总览未接门面 API，逐条件 pending 又误用了“新解锁数量”文案；正式启动器只依赖少数 runner 手工禁用进度提交，未对全部 smoke / 自动化入口统一隔离。修复后专项 smoke、DataLoader schema、headless、四条 Replay v6 与全量 pre-commit 复跑通过，未留下 P0 / P1 / P2 问题。
