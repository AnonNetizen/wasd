# 2026-07-27 会话日志

## ADR #161 主／子英雄组合与七元素战斗系统

- 用户要求把单角色升级为“主英雄 + 子英雄”：主英雄决定主体外观、基础属性、被动与技能 1/2，子英雄只决定强调色与技能 3/4；本期实现开局选择，局内换人只预留数据和接口。首发角色为冷静与愤怒，组合名使用可本地化 `{main}·{sub}` 模板，局外禁止同英雄组合。
- `characters.json` 升至 schema v3，新增 `character_primary_a` / `character_primary_b`、`hero_passives.json` 与纯数据 `HeroCompositionResolver`。四技能固定使用 `skill_1`～`skill_4` 槽位并按槽位保存独立冷却；主英雄能力强度、范围、效率、持续时间作用于全部四技能，子英雄属性不参与组合。
- 战斗数据从 `damage_type` 迁移到七元素 `element_id`，新增 A / B / C、AB / BC / CA 和中性元素及显式组合表；现有武器、敌人、投射物、机关和持续伤害统一迁为中性。冷静主英雄只减免纯 A，愤怒主英雄只减免纯 B，复合元素不触发被动。
- 玩家防御改为超量护盾 → 普通护盾 → 元素被动 / 护甲 → 生命；实现普通护盾恢复、指数超量护盾衰减、按击破前护盾比例计算的护盾门，并删除统一受伤后 0.7 秒无敌。敌人接触伤害改为逐敌人 `contact_interval` 独立计时。
- `SkillSystem.cast_slot()` 管理四槽、共享能量与快照。静域屏障、镇静脉冲、怒意超频、激怒标记均由通用效果原语、状态和按来源覆盖的修饰器实现；减速取最强并刷新，超频刷新不叠加，敌方移速强化刷新不叠加，易伤最多五层且只放大玩家归因的直接 / 持续伤害。
- 新增可池化圆形投射物屏障与能量球。屏障只拦敌方投射物，玩家弹穿透，死亡或重施回池；玩家归因击杀使用 `RNG.drop` 判定 10% 能量球，恢复 25 点，满能量不吸附 / 拾取。空格冲刺使用移动或瞄准方向、碰墙停止、穿敌、独立冷却与短暂无敌。
- 正式输入改为左键开火、右键 / 左 Shift / E / R 四技能、空格冲刺、F 交互，并补齐手柄映射；删除 `use_active_item` 占位。所有业务输入继续走 G.U.I.D.E、生成 action 常量与 `InputService` 归一化 intent，Replay 记录组合、四技能和冲刺。
- 正式流程改为标题开始 → 英雄组合选择 → Loading → 游戏；重新开始沿用当前组合，继续游戏直接恢复。HUD 增加生命、普通 / 超量护盾、能量、四技能、冲刺、状态与能力 / 防御详细属性；中英文与手柄焦点导航同步。开发者测试岛增加主 / 子英雄、四技能、元素注入、防御 / 能量控制和状态观察，同时保持正式 boot / title 与 release 零耦合。
- Meta / Run / Replay schema 分别升级为 v2 / v5 / v3。Meta v1 迁移保留 Gear Mod；旧 Run v4 显示一次兼容提示后删除；旧 Replay 明确拒绝。Run v5 保存组合、四槽、资源、防御、冲刺、状态、屏障、能量球和接触计时；四条黄金回放已按新 schema 重录，覆盖两种主英雄、四技能、冲刺、死亡和升级选择，运行时重放摘要与模块地图 hash 均通过。
- 完整验证通过 contracts、数据 / DataLoader schema、headless boot、input / loading / runtime / save / replay / replay-input / L1 / actor / module-world / F9 / Gear Mod / settings / UI / VFX / debug tools / standalone debug arena / release 隔离等 smoke，四条 Replay v3 黄金回放运行时重放通过且模块地图 hash 保持不变。事实审查过程中修正了无池屏障兜底、角色回退特判、跨槽重复屏障未全局替换、调试 / 回放死亡未先穿透新防御层、F9 仍假设伤害直达生命、Settings 仍断言旧 E 交互、HUD 未聚合敌方减速 / 加速 / 易伤状态、Loading 组合面板重入与坏组合恢复、Run v5 断言及黄金回放缺少显式四技能 / 冲刺事件。本任务按 ADR #143 未运行 startup/performance probe 或 Profiler。

## ADR #162 配置驱动的技能／被动描述数值

- 用户要求把当前英雄 / 技能描述迁移到配置数值，并新增长期规则：以后玩家描述中很可能调整的数值尽量不要硬编码。
- 新增纯数据 `SkillValueResolver`，统一处理技能能量成本、目标范围、effect 参数与强度 / 范围 / 效率 / 持续时间缩放；`SkillSystem` 改为调用该解析器，避免运行时与展示各维护一套公式。
- 新增 `SkillDescriptionFormatter`，以 `{cost_energy}`、`{target_radius}`、`{effect_1_duration}`、`{effect_1_modifier_1_value_bonus_percent}`、`{param_multiplier_reduction_percent}` 等通用命名 token 从 `skills.json` / `hero_passives.json` 生成完整句子，不按 hero / skill / passive id 特判。
- 冷静 / 愤怒的两个被动和四个技能中英文描述已移除硬编码的消耗、半径、生命、幅度、持续时间、层数与减免；英雄组合选择卡现在显示技能 1–4 的完整描述，并以所选主英雄的能力属性解析全部四槽。
- `validate_data.py` 会拒绝配置无法提供的描述 token，DataLoader schema 回归增加技能 / 被动未知 token 负例；L1 覆盖配置与能力缩放后的格式化值，Loading smoke 覆盖组合卡不泄漏未解析占位符。
- `.codex` / `.codebuddy` / `.opencode` / `.claude` 四平台规则、GDD、词表、Locale / SkillSystem 模块文档、测试策略、AI 导航和知识索引同步 ADR #162：玩家描述里的可调数值必须由对应配置和统一格式化器注入，不得在 `*_desc` 译文中重复写死。
- 本任务按 ADR #143 不运行性能 probe。

## ADR #163 静域屏障跨边界拦截

- 用户明确静域屏障的敌弹规则：盾外不能射入盾内、盾内不能射到盾外，但进入盾内的敌人可以攻击盾内目标。
- `ProjectileBarrier.projectile_boundary_hit_fraction()` 使用投射物半径扩张后的圆周与本帧线段求交；外→内、内→外和穿圆的外→外会返回最先交点，内→内与不穿圆的外→外返回无命中。
- `Bullet` 只让 `team_enemy` 查询该边界；敌弹首个物理帧从射手开火位置扫到弹体当前位置，避免远程敌人的枪口偏移直接生成在圆周另一侧。该起点和待处理标记进入子弹快照并在对象池重置 / 释放时清理，玩家弹继续完全忽略屏障。
- 事实审查发现正式敌弹还会从 `active_projectile_blockers` 普通目标组二次命中部署物；已统一把 `active_deployables` 排除出普通伤害目标链，确保屏障只由跨边界链结算。L1 使用正式敌弹目标组验证盾内敌弹命中盾内玩家，并覆盖圆内同侧、圆外同侧、外→内、内→外、整圆穿越、双向枪口越界、弹体回收与首帧扫掠快照恢复。
- GDD、SkillSystem / Gameplay Runtime 模块文档、测试策略、AI 导航、ADR、项目记忆和机器当前状态已同步；本任务按 ADR #143 不运行性能 probe。
- targeted pre-commit、GDScript / project / semantic lint、JSON / docs health、headless boot、L1、runtime、save 与 module-world smoke 通过；runtime / save / module-world 的坏档或 map hash 错误为测试主动注入。四条 golden 在主工作区被既有未提交 `characters.json` 纯缩进变化的原始数据指纹挡住；临时 clean worktree 又因首次导入缺 Godot global class cache 而不构成有效 replay 结果，因此未重录或宣称通过。

## ADR #164 全开放平地与空地动态刷怪

- 新增 `module_flat_ground`：11×11 共 121 格全部为 floor，四边完全开放，没有墙、机关、奖励、装饰或 placement，只允许 0°。正式 `template_pool` 与 fallback 的非固定槽全部改用平地；固定起点、目标、撤离与既有模块 / 技术首片保留。
- `modules/*.json` 升至 schema v3，所有模块删除敌人出生 placement；`module_place_enemy_spawn` 从词表、生成常量、DataLoader、Python 校验器、编辑器、模板与 baker 中彻底删除，不保留运行时兼容。17 个模块统一重新 Validate / Bake / Approve，批准 hash 与生成场景已更新。
- `module_worlds.json` 升至 schema v2，新增 `first_visit_enemy_spawn`：每个非起点槽 4–6 个敌人、1.5 秒预警，追击者 / 群集 / 潜行 / 远程 / 重甲分别在 0 / 60 / 240 / 300 / 420 秒解锁并使用 100 / 45 / 18 / 16 / 25 权重。双端 schema 拒绝未知敌人、非法计数 / 时间 / 权重与不足 6 个有效空地格的正式模板。
- socket 兼容从整边完全一致改为旋转后边缘开放格至少有一个交集；世界外圈封边与完整 99×99 flood-fill 保持。`ModuleWorldManager.empty_floor_positions_at()` 返回旋转、封边后仍为 floor 且排除全部 gameplay placement footprint 的格心，按行列稳定排序，不检查玩家 / 动态实体，也不设安全半径。
- `GameplayRunLoop` 把邻域流式激活与首次实际进入拆开：3×3 预加载只挂场景、静态内容和旧快照；第一次进入非起点槽时，用 `RNG.spawn` 无放回确定位置和已解锁敌种，立即把 `telegraphing/spawned`、剩余时间与 `enemy_id + world_position` 计划写入 Run v5 槽位。预警结束时同时从五个独立敌人池生成；暂停 / 卸载冻结，返回 / 续局重建同一 VFX，玩家站上选中格不重抽，清空后不再刷新。
- 新增数据驱动 `enemy_spawn_telegraph` cue 与 `presentation_module_encounter`；正常模式按配置时长缩放地面环，reduced-motion 使用静态高对比 gameplay-boundary 变体，不允许完全隐藏。VFX 本身不进存档。
- Run 保持 v5，Replay 保持 v3；玩法 map hash 变化自然使旧模块局失效，不增加旧回放迁移层。完整验证、四条黄金重录与最终事实审查结果在本任务提交记录和 `current_state.json.last_verified` 中维护；按 ADR #143 不运行性能 probe。
- 最终验证通过 contracts、数据 / DataLoader schema、三层 lint、模块 Validate / Bake / Approve、模块编辑器、headless boot、runtime / save / VFX / replay、完整 / 技术首片 module-world smoke 与四条重录后的 Replay v3 黄金回放。事实审查补上了 fixed / fallback 非起点模块也必须至少有 6 个有效空地格的双端校验和负例；未发现其余 P0 / P1 / P2 问题。测试主动注入的坏档 / map hash 错误与 Godot headless 退出时既有 RID / resource leak 日志不影响 PASS。

## ADR #165 武器后坐力、弹道扩散与控制 Mod

- `weapons.json` 升至 schema v3：每把武器必填 `recoil` 与完整锥角 `spread_angle_max`，根级 `recoil_model` 数据化后坐上限、扩散指数、后移距离 / 时长 / 速度上限和 180° 运行时扩散硬上限；基础枪使用当前配置值。
- 新增纯数据 `WeaponRecoilResolver`。WeaponSystem 每次扳机快照中心瞄准方向，每颗弹丸固定消耗一次 `RNG.combat` 并独立抽取锥内方向；零扩散不跳过随机数，多弹丸共用中心枪口且只发一次 `weapon_fired` context。
- Player 以线性衰减反向冲量叠加正常移动，向量按数据速度上限钳制并走 `CharacterBody2D` 碰撞 / 世界边界；冲刺期间不新增或应用后移，但已有冲量继续按 `GameClock` 衰减。暂停冻结，Run v5 在同版本内保存速度、剩余时间和总时长。
- `camera_feedback.json` 升至 schema v2，新增独立 `WeaponRecoilShake` Phantom Camera emitter。武器振幅按后坐比例动态缩放，连射刷新并保留当前较强振幅；`screen_shake=false` 立即停止受击 / 武器震屏但不改变弹道、反冲或玩法 RNG。鼠标瞄准改用指针相对固定屏幕中心，排除相机噪声。
- 新增后坐阻尼与扩散稳定两张普通武器 Mod：前者修正 `recoil`，同时影响扩散 / 后移 / 震屏；后者只修正 `spread_angle_max`。rank、drain、拆解、掉落与双语文本均数据驱动；Gear Mod 详情负乘法显示修正为 `-N%`。
- DataLoader 与 Python schema、契约、数据 / Locale 手册、GDD v1.35、ADR、Gameplay Runtime、Phantom Camera、Gear Mod、Save / Replay、测试策略、AI 导航和三层 AI 记忆同步。Replay 输入格式保持 v3，四条黄金回放按新数据指纹重录并通过 runtime summary。
- 验证通过 contracts、数据 / DataLoader schema、三层 lint、L1、Gear Mod、input / settings、runtime / save、actor scene、完整 / 技术首片 module-world、headless boot、Replay smoke / input smoke 与四条黄金回放。事实审查额外修正了 `amplitude_exponent=0` 时零后坐不应产生最大震屏的运行时边界；按 ADR #143 未运行性能 probe。
