# 2026-07-27 会话日志

## ADR #161 主／子英雄组合与七元素战斗系统

- 用户要求把单角色升级为“主英雄 + 子英雄”：主英雄决定主体外观、基础属性、被动与技能 1/2，子英雄只决定强调色与技能 3/4；本期实现开局选择，局内换人只预留数据和接口。首发角色为冷静与愤怒，组合名使用可本地化 `{main}·{sub}` 模板，局外禁止同英雄组合。
- `characters.json` 升至 schema v3，新增 `character_primary_a` / `character_primary_b`、`hero_passives.json` 与纯数据 `HeroCompositionResolver`。四技能固定使用 `skill_1`～`skill_4` 槽位并按槽位保存独立冷却；主英雄能力强度、范围、效率、持续时间作用于全部四技能，子英雄属性不参与组合。
- 战斗数据从 `damage_type` 迁移到七元素 `element_id`，新增 A / B / C、AB / BC / CA 和中性元素及显式组合表；现有武器、敌人、投射物、机关和持续伤害统一迁为中性。冷静主英雄只减免纯 A，愤怒主英雄只减免纯 B，复合元素不触发被动。
- 玩家防御改为超量护盾 → 普通护盾 → 元素被动 / 护甲 → 生命；实现普通护盾恢复、指数超量护盾衰减、按击破前护盾比例计算的护盾门，并删除统一受伤后 0.7 秒无敌。敌人接触伤害改为逐敌人 `contact_interval` 独立计时。
- `SkillSystem.cast_slot()` 管理四槽、共享能量与快照。静域屏障、镇静脉冲、怒意超频、激怒标记均由通用效果原语、状态和按来源覆盖的修饰器实现；减速取最强并刷新，超频刷新不叠加，敌方移速强化刷新不叠加，易伤最多五层且只放大玩家归因的直接 / 持续伤害。
- 新增可池化圆形投射物屏障与能量球。屏障只拦敌方投射物，玩家弹穿透，死亡或重施回池；玩家归因击杀使用 `RNG.drop` 判定 10% 能量球，恢复 25 点，满能量不吸附 / 拾取。空格冲刺使用移动或瞄准方向、碰墙停止、穿敌、独立冷却与短暂无敌。
- 正式输入改为左键开火、右键 / 左 Shift / E / R 四技能、空格冲刺、F 交互，并补齐手柄映射；删除 `use_active_item` 占位。所有业务输入继续走 G.U.I.D.E、生成 action 常量与 `InputService` 归一化 intent，Replay 记录组合、四技能和冲刺。
- 正式流程改为标题开始 → 英雄组合选择 → Loading → 游戏；重新开始沿用当前组合，继续游戏直接恢复。HUD 增加生命、普通 / 超量护盾、能量、四技能、冲刺、状态与能力 / 防御详细属性；中英文与手柄焦点导航同步。开发者测试岛增加主 / 子英雄、四技能、元素注入、防御 / 能量控制和状态观察，同时保持正式 boot / title 与 release 零耦合。
- Meta / Run / Replay schema 分别升级为 v2 / v5 / v3。Meta v1 迁移保留 Gear Mod；旧 Run v4 显示一次兼容提示后删除；旧 Replay 明确拒绝。Run v5 保存组合、四槽、资源、防御、冲刺、状态、屏障、能量球和接触计时；四条黄金回放已按新 schema 重录，覆盖两种主英雄、四技能、冲刺、死亡和升级选择，运行时重放摘要与模块地图 hash 均通过。
- 完整验证通过 contracts、数据 / DataLoader schema、headless boot、input / loading / runtime / save / replay / replay-input / L1 / actor / module-world / F9 / Gear Mod / settings / UI / VFX / debug tools / standalone debug arena / release 隔离等 smoke，四条 Replay v3 黄金回放运行时重放通过且模块地图 hash 保持不变。事实审查过程中修正了无池屏障兜底、角色回退特判、跨槽重复屏障未全局替换、调试 / 回放死亡未先穿透新防御层、F9 仍假设伤害直达生命、Settings 仍断言旧 E 交互、HUD 未聚合敌方减速 / 加速 / 易伤状态、Loading 组合面板重入与坏组合恢复、Run v5 断言及黄金回放缺少显式四技能 / 冲刺事件。本任务按 ADR #143 未运行 startup/performance probe 或 Profiler。

## ADR #162 配置驱动的技能／被动描述数值

- 用户要求把当前英雄 / 技能描述迁移到配置数值，并新增长期规则：以后玩家描述中很可能调整的数值尽量不要硬编码。
- 新增纯数据 `SkillValueResolver`，统一处理技能能量成本、目标范围、effect 参数与强度 / 范围 / 效率 / 持续时间缩放；`SkillSystem` 改为调用该解析器，避免运行时与展示各维护一套公式。
- 新增 `SkillDescriptionFormatter`，以 `{cost_energy}`、`{target_radius}`、`{effect_1_duration}`、`{effect_1_modifier_1_value_bonus_percent}`、`{param_multiplier_reduction_percent}` 等通用命名 token 从 `skills.json` / `hero_passives.json` 生成完整句子，不按 hero / skill / passive id 特判。
- 冷静 / 愤怒的两个被动和四个技能中英文描述已移除硬编码的消耗、半径、生命、幅度、持续时间、层数与减免；英雄组合选择卡现在显示技能 1–4 的完整描述，并以所选主英雄的能力属性解析全部四槽。
- `validate_data.py` 会拒绝配置无法提供的描述 token，DataLoader schema 回归增加技能 / 被动未知 token 负例；L1 覆盖配置与能力缩放后的格式化值，Loading smoke 覆盖组合卡不泄漏未解析占位符。
- `.codex` / `.codebuddy` / `.opencode` / `.claude` 四平台规则、GDD、词表、Locale / SkillSystem 模块文档、测试策略、AI 导航和知识索引同步 ADR #162：玩家描述里的可调数值必须由对应配置和统一格式化器注入，不得在 `*_desc` 译文中重复写死。
- 本任务按 ADR #143 不运行性能 probe。
