## ADR #196：统一效果框架与本地 Gear Mod

- 用户要求把大量后续 Mod / 效果扩展建立在统一数据驱动框架上，并允许玩家本地包新增 Gear Mod。新增每局 `GameplayEffectRuntime`、`EffectPrimitiveRegistry` 与 `EffectExecutionGateway`；7 类触发、7 类条件与 10 类动作统一使用 `program_id + trigger + conditions[] + actions[] + proc_chance + internal_cooldown`，概率走 `RNG.combat`、时间走 `GameClock`，FIFO 链深上限 8、每物理帧动作预算 256。
- Skills 升 v3，以 `programs[]` 进入运行时；Gear Mod 升 v6，以可组合 `modifier / program / board_rule` components 取代旧 kind / map / grid 分支。现有属性 Mod 转为 modifier，刷怪笼转为当前模块周期 program，石头转为 `occupy_only`；运行时快照保存 ICD、周期与 action state，刷怪计划失败重试和续局均不重抽。
- 本地 manifest 升 v2：动态 Gear Mod ID 必须属于 `mod_<package_id>_` 命名空间；包只能追加 Gear Mod、官方奖励池贡献、官方敌人掉落和双语 locale，只能组合官方原语。包先独立校验，坏玩法包单独禁用；活动 Run / Replay 拒绝重载，标题新增只读 Mod 状态面板与显式重载。
- 媒体注册表支持受限 PNG / WebP / JPEG 与 Ogg Vorbis / MP3 / WAV 非循环 SFX；校验路径、文件头、解码、尺寸 / 时长 / 数量 / 总量和命名空间。缺失或损坏媒体只诊断并回退；本地 Gear Mod 可用 `codex_icon_path` 与 `placement_sfx_id`，展示媒体不进入 gameplay hash。
- Save 升 Run v19、Replay 升 v9、游戏升 v1.18；精确保存 `mod_environment[{id,version,gameplay_hash}]`。旧 Run v18 / Replay v8 与缺包、版本、玩法 hash 不匹配均保留原文件并拒绝继续 / 播放，不当作普通坏档隔离；四条黄金回放已按 v9 重录并 4/4 复跑通过。
- 遗物数据、资源池、契约、locale、测试岛入口、四平台 `/new-relic` 与任务模板全部删除，改为 `/new-gear-mod` 与“加 Gear Mod”。历史 ADR、旧会话日志、报告和历史输出保持原文；新增 ADR #196，并同步 GDD、词表、测试策略、代码文档、AI 导航、知识索引、项目记忆与工作包。

## ADR #197：代码架构治理与 fail-closed 首片

- 用户批准按“先正确性、再边界、后渐进拆分”治理当前架构，不做大爆炸重写。Replay v9 在输入或决策丢弃计数非零时拒绝保存 / 加载，停止录制仍保留诊断；两类事件分别覆盖精确容量与 `MAX + 1`。
- SaveManager 将主档状态分为缺失、可隔离损坏和需 preserve 不兼容：preserve 主档立即拒绝且不碰备份；损坏主档先移入 `.broken` 再尝试 `.bak`；已尝试且 preserve 的备份保留原字节。FormalClientBoot 不再对空 envelope 调用 `delete()`，防止不兼容主档 / 备份被界面流程静默删除；`save-smoke` 使用完整 3×3 主备矩阵和标题继续入口锁定行为。
- `godot_bridge.py` 将所有 headless smoke 统一到隔离用户目录、精确成功标记和标准 fatal 门禁；仅对已实证命令开放已知 Godot 4.7.1 shutdown-only 报告，普通 smoke 出现同类泄漏仍失败。Python 回归用真实哨兵目录覆盖成功 / 故障退出、缺成功标记和额外未登记错误。
- RunLoop 缺 MapManager、WorldBackground、WeaponSystem 或 GameplayHud 时统一经 `_fail_run_start()`，玩家加载模式只发一次 `run_prepare_failed`；FormalClientBoot 清理 LoadingScreen、半成品 RunLoop、运行活动与相关对象池并回到标题。
- `WorldEventController` 新增同步 `{ok, reason}` 奖励投放边界：只有金币入账或 Gear Mod 实体实际生成成功后才提交奖励、成功次数和终态；失败保持 pending，Run v19 快照恢复后重试不重抽、不重复扣费或献祭。`reward_requested` 保留为成功后的观察 signal。
- UIManager 新增任意受管节点移除与意外 `tree_exited` 自愈，FormalClientBoot 不再直接释放受管面板；UIManager 通过 `InputService.set_ui_stack_active()` 单向推送栈事实，删除 InputService 对 UIManager 的反向查询、订阅与 deferred 初始化规避。
- 本阶段保持 Meta v4、Run v19、Replay v9、游戏 v1.18、平衡结果和公开存档格式。提交前事实审查发现并修复 Boot 删除 preserve 备份、smoke 泄漏豁免过宽及验收矩阵缺口；后续 GUT / CI、效果原语参数、Mod 预算、RunLoop / DataLoader / modifier / Enemy 提取继续按单职责独立提交。未运行性能 probe；视觉、听觉与手感仍待用户人工验收。
