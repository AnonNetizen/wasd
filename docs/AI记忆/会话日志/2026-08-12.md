# 2026-08-12 会话日志

## ADR #198：Godot Bridge 并行项目隔离

- 根因确认：既有 Bridge 已隔离 `APPDATA` / XDG / `HOME` 与 GUT JUnit，但多个 Godot 进程仍共享仓库 `client/.godot`，因此导入、全局类、UID、shader / editor cache 会竞争并产生陈旧 cache、级联 parse 假错与残留进程问题。
- `tools/godot_bridge.py` 现在把只读 Godot 命令重新执行到逐进程临时项目快照；快照只复用 `.godot/imported`、全局类、UID 与 scene group 等安全 cache seed，复制前后比较源码 manifest，遇到写入会重试并最终 fail closed。每个 child 同时拥有私有 `.godot`、`user://` 与测试结果目录。
- `vfx-bake`、`module-bake`、`capture-golden-replay`、`capture-gear-mod-pickup` 继续对原项目写回，并由按绝对项目路径派生的跨进程锁全程独占；快照仅在创建期间短暂持锁。裸 Godot 或绕过 Bridge 的 runner 仍不承诺并行安全。
- Python Bridge 回归覆盖只读 / writer 路由、项目参数替换、安全 cache seed、manifest 重试、私有环境重执行、控制台编码降级及既有 smoke / GUT fail-closed 行为。真实从同一 source 同时启动 `gut --test-dir unit` 与 `headless-boot`，两边均创建私有快照；GUT JUnit 与 FormalClientBoot marker 均通过，无 Bridge fatal 或 traceback。
- 本次不改 gameplay、数据、存档 / 回放协议或 golden；Meta v4、Run v19、Replay v9、game v1.18 保持。未运行性能 probe、人工验收或任何 golden 重录。

## ADR #199：三站式传送台网络

- 每局通过 `RNG.world` 确定性布置三座 `teleporter_network_primary` 传送台，两两模块坐标曼哈顿距离至少为 4。受约束限量组在临时 assignment 上回溯，三座全部找到后才一次性提交；无解只接受 checked-in 三站 fallback，fallback 仍失败则整局准备失败。
- 模块世界 schema 升至 v6，模块 JSON schema 升至 v5；`module_place_teleporter` 使用严格 `{type,cell,network_id,interaction_radius}` payload，中心可走格交互半径为 180 px，传送台格属于 protected footprint。生成顺序固定为 `start → objective → teleporter → world events → ordinary`。

- 新增 `GameState.TELEPORT_CHOICE`，SceneTree 与 `GameClock` 均冻结；`UI_BACK` 取消回到 `PLAYING`，暂停菜单可叠在选择面板上方并在关闭后恢复原选择态。全黑帧依次执行 `Player.teleport_to()`、ModuleWorld `tick()` / 流送事务、相机 `snap_to_target()`、HUD / 交互刷新；失败不得产生部分移动，成功不恢复生命、护盾、状态或冷却，也不提供无敌或额外冷却。

- 自动门禁已完成：contracts、数据 / schema、23 模块 bake 与 114 断言 bake smoke、完整 / technical module-world、teleporter、save、loading、runtime、replay / replay-input、366 项 / 2707 断言完整 GUT、三层 lint、docs health、headless boot 均通过。四条 Replay v10 golden 已在 data fingerprint `0868a6914c6457bd4eac1397ad1830d80f9c8d2951707b53a5f8450f8657e967`、module map hash `14f5e6b7d625658228b0c6866ba515d723b67ec8878957e499a96ff4ebd32748` 下重捕获并 4/4 复跑；`golden_basic_run` 新增原始 `interact` → `teleport_choice` → 非零淡出入完整事务覆盖。事实审查发现的异步回放提前结算、选择态真实续局与暂停覆盖续局漏测均已修复并覆盖；semantic lint 仅保留两条既有 `DataSourceReader` advisory。性能 probe 未运行。视觉、双语布局、真实手柄焦点、淡出淡入观感与传入危险区域手感保持待用户 L5 人工验收，AI 不代验。

## ADR #200：传送选择改为非暂停

## ADR #203：应用关闭保存确认

- `FormalClientBoot` 禁用 Godot 自动接受退出，把标题页“退出”、窗口关闭按钮和 `NOTIFICATION_WM_CLOSE_REQUEST` 统一路由到暂停型 `ApplicationQuitModal`；确认框只提供本地化的“保存并退出”和“取消”，取消会恢复进入前状态并允许再次关闭。
- 加载中的关闭请求先排队，待 Run 成功激活或失败回到标题后再显示，避免确认框覆盖并破坏 `LoadingScreen` 栈。若已有其他 `ConfirmationModal`，先按其取消语义完整移除再显示应用退出确认。
- 确认时先立即移除退出框并恢复底层真实状态；只有 `PLAYING` / `PAUSED` / `REWARD_CHOICE` 的有效 Run 通过新增公开 `GameplayRunLoop.save_run_snapshot()` 复用 Run v20 快照写入，标题与其他无有效 Run 状态保留既有存档后退出。保存失败不退出，改为重新显示可重试 / 取消的失败提示；暂停菜单的原“保存并退出”也复用同一公开保存路径。
- Meta v4 / Run v20 / Replay v10 / 游戏 v1.19、data fingerprint 与 module map hash 均不变。自动验证已完成：contracts、数据、本任务 file-scoped pre-commit、三层 lint、docs health、`loading-smoke`、`ui-manager-smoke`、`save-smoke`、`runtime-smoke`、`settings-smoke`、370 项 / 2733 断言完整 GUT 与 headless boot 均通过；最新 `loading-smoke` 覆盖加载排队，保存失败、重复取消、已有确认框替换及中英文文案。semantic lint 两条 `DataSourceReader` advisory 为既有未改代码，本轮接受且不处理。事实审查为 Critical=0、High=0、Medium=0。性能 probe 未运行；双语布局、真实窗口关闭 / 系统快捷键、焦点恢复和保存失败提示可读性待用户 L5 人工验收，AI 不代验。
