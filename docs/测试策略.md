# 测试策略

> **权威范围**：本文件定义测试层级、按风险选证据、覆盖率、回放、性能和人工验收政策；具体模块测试入口由模块文档与测试工具提供。

## 1. 原则

- 每次只根据当前差异选择最低充分证据，不沿用上一任务的验证矩阵。
- 能由静态校验发现的问题不靠 Godot smoke 重复证明；能由目标测试覆盖的问题不无差别跑全仓。
- 一个不变量只指定一个权威测试层；跨模块变化再追加一条关键流程闭环，不按字段、helper 或调用方数量倍增用例。
- 自动测试与人工验收分开：L0～L4 由机器执行，L5 只由人工执行。
- 测试结果留在终端、CI、PR 和 Git 历史，不写入长期文档或 current state。

## 2. 测试层级

| 层级 | 目标 | 典型入口 |
|------|------|----------|
| L0 静态 | 语法、schema、契约、locale、项目红线 | sync / validate / lint / docs health |
| L1 单元 | 纯函数、资源、状态机、边界条件 | GUT unit、Python unit |
| L2 集成 | 多模块接线、生命周期、失败路径 | GUT integration、专项 smoke |
| L3 运行时 | 正式项目启动与真实场景闭环 | headless boot、runtime / save / input smoke |
| L4 回归 / 性能 | 稳定行为、确定性、预算 | golden replay、perf probe |
| L5 人工 | 视觉、听觉、手感、色弱、真实设备 | 用户 checklist |

## 3. 按变化类型选择证据

| 变化 | 最低责任 |
|------|----------|
| 文档 / AI 配置 | 文档健康、相关工具单测、diff check |
| 私有重构且行为不变 | 目标单测 + 受影响模块 smoke；golden 只重跑 |
| 公共 API / signal / 生命周期 | L1 + 调用方集成 + 对应 smoke |
| 数据值 | validate + 文件范围 pre-commit；只有现有专项真实覆盖该值时追加 |
| 数据 schema / loader | contracts + validate + schema regression + 受影响模块 smoke |
| locale / UI 文案 | locale 校验 + 对应 UI smoke；英文布局留给 L5 |
| 输入 / 重绑定 / Replay intent | input + settings + replay-input + runtime |
| Combat / 状态 / 效果原语 | 目标 GUT + L1 / runtime；稳定摘要改变时评估 golden |
| autoload 接口 | 单元 / 集成 + headless boot |
| 存档 schema / wire | 迁移或明确拒绝测试 + save / loading + 备份 / 损坏路径 |
| Replay schema / 确定性 | replay smoke + replay-input + checked-in golden |
| 性能敏感算法 | 目标功能回归；仅用户明确要求时运行 perf probe |

模块文档可以列出具体命令，但不得把逐 helper 矩阵复制回本文件。

## 4. 通用门禁

基础静态入口：

```powershell
python tools/sync_contracts.py --check
python tools/validate_data.py
python tools/test_data_loader_schema.py
python tools/lint_gdscript_rules.py
python tools/lint_project_rules.py
python tools/lint_semantic_rules.py
python tools/docs_health_check.py
```

Godot 命令统一经 `python tools/godot_bridge.py --project client <command>` 运行。只读命令可由 Bridge 隔离并行；写回源码的 bake / capture 命令保持独占。

提交前对本次文件运行一次 file-scoped pre-commit；只有 hook / lint / validator 本身、大型全仓治理或发版准备才考虑 `--all-files`。

## 5. 风险归属与测试写法

- 覆盖率用于发现无主风险，不作为逐文件测试数量指标；删除实现或重复分支时应同步删除只证明该实现细节的测试。
- 测试命名 `test_<行为>_<期望>`，固定 seed，玩法时间使用假 `GameClock` 或正式时钟 seam。
- 负例必须断言失败原因或诊断；不能只看进程退出码 0。
- 测试默认隔离 `user://`，不得读取或覆盖玩家真实设置、存档、回放和本地 Mod。
- 同一风险同时被静态 schema、单元测试和专项 smoke 覆盖时，保留最接近权威来源的一层与必要的跨模块闭环；full GUT、runtime smoke 与全量 replay 只在各自风险确实进入 diff 时追加。

## 6. 黄金回放

- 只有稳定玩法行为、协议或玩法指纹有意改变时重录。
- bugfix、测试补强和内部重构默认只重跑，不重录。
- 重录必须审查输入 / 决策丢弃计数、稳定摘要、data fingerprint 和 module map hash，并在 commit 说明原因。
- 权威全量入口为 `python tools/godot_bridge.py --project client replay-regression`。

## 7. 性能

- `perf-probe` / `startup-probe` 只在用户当次明确要求、性能专项或发行门禁明确要求时运行。
- 性能结果必须与同环境基线比较；未运行不得推定通过。
- 性能敏感改动即使不跑 probe，也应保留确定性、访问上限、实体数量或算法边界测试。

## 8. L5 人工验收

- 明确标为人工检查、人工验收、L5、真实设备、视觉、听觉、手感、可读性或色弱验收的项目只交给用户。
- AI 只提供前置条件、步骤、预期现象和已知风险；用户给出结果后可协助分析和修复。
- 自动化验证仍必须完成，不能因存在 L5 而跳过 L0～L4。
