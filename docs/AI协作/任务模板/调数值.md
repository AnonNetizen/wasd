# 任务模板：调数值（平衡迭代）

> **AI 修改说明**：修改本任务模板前先读 `docs/AI协作/文档维护指南.md`。模板变化通常需要同步 `docs/AI协作/README.md`、`docs/AI协作/上下文预算.md`、相关 subagent / command（如有）、`AGENTS.md` 的高频任务表（如入口变化）。

## 必读
1. 当前平台编码规则入口（见 `AGENTS.md` 第 3 步）第 3 节（数据与逻辑分离）
2. `client/data/README.md`（数值配置手册）
3. 目标 `client/data/*.csv` / `client/data/*.json` 的目标条目
4. （改后）`tests/replays/golden_*.replay` 的存在情况

## 核心约束
- ✅ 只改 `client/data/` 下的 CSV / JSON 文件
- ✅ 平表数值优先 CSV，复杂配置优先 JSON；若发现格式不合适，先同步 `client/data/README.md` 再迁移
- ❌ 绝不改代码常量
- ✅ 新增 / 改名字段时同步 `client/data/README.md`
- ✅ 每次按当前改动重新分级，不继承上一项大型任务的验证矩阵
- ✅ 大改动后只运行**确实覆盖目标变量**的黄金回放；无覆盖时改用目标测试并明确验证缺口

## 步骤
1. 找到目标条目 → 改值
2. 确认字段单位 / 范围已在 `client/data/README.md` 写清
3. 对“已有字段的小幅调参”先跑 `py -3 tools/validate_data.py`，再运行只包含本次文件的 `pre-commit run --files ...`；最终 hook 已覆盖 schema 时不再重复跑完整 schema 回归
4. 只有修改 schema / 契约 / 加载路径、启动默认值，或测试策略明确要求时，才追加 DataLoader schema、headless boot、runtime smoke 等专项
5. 大改动（如基础属性体系 / 难度曲线）先审查 golden 的输入与稳定摘要是否覆盖目标变量，再用 `replay-runner` 对比现有基线
6. 只有已覆盖的稳定语义或 data fingerprint 确实改变时才重录；不得提交仅由录制时间、tick、生成 hash 等非语义噪声构成的 golden diff
7. 玩家移速、操控响应等手感结论交用户做 L5 人工验收；AI 只报告数据值、自动化结果和覆盖边界

## 自检
- [ ] 没碰代码
- [ ] 字段值在合法范围
- [ ] 字段说明文档仍准确
- [ ] hook 全过
- [ ] 没有重复运行同一昂贵门禁
- [ ] 大改动有“测试确实覆盖目标变量”的回归证据；无覆盖时已明确说明
- [ ] 手感项保留为待人工验收

## 不需要做的
- 一般不需 ADR（除非是难度曲线哲学级改动）
- 一般不需 AI 记忆同步
- 纯已有数值字段调整一般不需 headless boot、runtime smoke、性能 probe 或黄金重录
