# 引擎集成（MCP / Bridge 接入指南）

> 现状：AI agent 默认只能"读写文件"。当引擎 MCP/Bridge 可用时，AI 可直接查询场景树、读 Resource、触发引擎命令——这是"AI 协作"的能力跃升。
> 本指南列出可接入的工具与配置方式，帮助 agent 与人决定**何时启用、如何启用**。
>
> 权威范围：本文档只维护标题所述主题的长期事实，不登记实现过程或完成历史。

---

## 1. Godot MCP（推荐关注）

社区已有多个开源实现，搜索关键词：`godot-mcp`、`godot mcp server`。

### 能力（典型）
- 读项目树（`res://` 下所有资源）
- 读场景节点结构（`.tscn` 解析）
- 读/写 `Resource`（`.tres`）
- 触发 `godot --headless` 跑特定场景
- 编辑器在线查询当前选中节点（需编辑器扩展）

### 何时启用
- AI 在大型场景树中找节点路径痛苦时
- 需要批量改 `.tres` Resource 时
- 跑 headless 测试需要交互式调试时

### 何时不启用
- 单纯的脚本 / JSON 改动 —— 文件操作够用，多一层 MCP 反而增加不确定性
- 任务能用本目录的"任务模板"覆盖时

### 配置位（待实际接入时填入）

```
- 安装步骤
- codebuddy mcp 配置示例（mcp.json 节选）

```

## 2. Unity MCP（备选，本项目暂不用）

社区也有 Unity MCP 实现，能力对齐 Godot 版（场景查询 / Prefab 操作 / 触发 Play 模式等）。本项目用 Godot，仅做记录，未来若多引擎并行再启用。

## 3. Aider / Continue / Cursor 风格的"实时验证"

并不是 MCP，但属于"引擎之外"的 AI 加速器：
- **Aider**：Git diff 驱动的 AI 编辑，可与 pre-commit hook 互补
- **Continue / Cursor**：IDE 级 AI，能实时跑 lint/test
- 本项目的 `实时验证回路.md` 已内建等效的本地反馈，**不强依赖 IDE**

## 4. 自研轻量 Bridge（正式 client 默认）

本项目先采用 `tools/godot_bridge.py` 作为轻量 Bridge，不依赖 MCP 协议；它把 Godot / 数据校验 / 场景树导出封装为稳定命令，供 AI 和 CI 前置验证使用。

当前命令：

```powershell
python tools/godot_bridge.py export-tree
python tools/godot_bridge.py validate-data
python tools/godot_bridge.py godot-version
python tools/godot_bridge.py headless-boot
python tools/godot_bridge.py --project client gut
python tools/godot_bridge.py runtime-smoke
python tools/godot_bridge.py settings-smoke
python tools/godot_bridge.py gear-mod-smoke
python tools/godot_bridge.py save-smoke
python tools/godot_bridge.py --project client module-world-smoke
python tools/godot_bridge.py --project client module-world-technical-slice-smoke
python tools/godot_bridge.py --project client startup-probe
python tools/test_godot_bridge.py
```

默认项目路径为正式 `client/`；需要指定其他 Godot 项目时使用：

```powershell
python tools/godot_bridge.py --project path/to/project headless-boot
```

### 项目隔离与并行

ADR #198 后，除纯 Python / 文本命令外，Bridge 会先判断 Godot 命令是否写回项目：

- boot、smoke、GUT、Replay regression、check 与其他只读命令默认复制到逐进程临时项目快照；每个 child 拥有私有 `.godot`、`APPDATA` / XDG / `HOME` 与测试结果目录，因此快照建立后可并行运行。
- 快照创建只在短暂的按项目路径跨进程锁内进行；复制前后比较源码 manifest，若期间发生写入则重试，连续变化时 fail closed。`.godot` 只复用 `imported`、全局类、UID 与 scene group 等安全 cache seed，不复制 editor 状态、shader cache、export credentials 或其他可写会话状态。
- `vfx-bake`、`module-bake`、`capture-golden-replay`、`capture-gear-mod-pickup` 会生成或更新仓库文件，继续使用原项目，并由 Bridge 在整个子进程期间取得同一独占锁。它们会等待正在创建的快照或另一 writer，但不会与只读 child 共享可写状态。
- 直接调用 Godot、直接调用工具脚本或新加写入命令却未登记到 Bridge 的 mutating command 集合，都不具备上述并行保证。新增命令必须先明确 read-only / source-writing 分类并补 `tools/test_godot_bridge.py`。

所有既有 `*-smoke` Bridge CLI 名称保持稳定，但其 parser、runner 与输出门禁统一来自 `client/tools/smoke_commands.json`。每条 smoke 默认使用临时 `APPDATA` / XDG / `HOME` 隔离 `user://`，必须命中 descriptor 的精确成功 marker，并在删除该命令逐项登记的整行 expected-error / shutdown 负例后拒绝剩余 `SCRIPT ERROR:` / `Parse Error:` / `Failed to load script` / `ERROR:`；带 preflight 的命令会把同一命令的精确 shutdown policy 传给每个子进程。未知 id、坏 catalog、缺 runner 或缺 marker 都 fail closed；空白 marker、无界 wildcard allowlist 以及与内建命令冲突的 id 在加载时拒绝。`formal_boot` runner 内部统一使用 `--test-command <id>`，直接 script / scene runner 不经过 FormalClientBoot。新增 smoke 时只扩 catalog 与 runner，不再给 Boot 增加一条专用 `--*-smoke` 分支。`gut`、`validate-data`、Replay / capture / perf / bake 等非 smoke 内建入口在命令分流时不读取 catalog，因此坏 smoke catalog 不会连带阻断独立工具。

`gut` 是本地与 CI 的 GUT canonical runner：默认运行 `res://tests/unit` 与 `res://tests/integration`，需要定位时可重复传 `--test-dir unit` / `--test-dir integration` 或 `res://tests` 下的其他目录。每次运行都使用私有项目快照，把 `APPDATA` / XDG / `HOME` 指向临时目录，在同一快照与隔离环境中先用阻塞式 `--headless --import` 完成全局类注册和资源导入，再运行 GUT，并将 JUnit 写入同一临时根；import 或测试输出出现 `GUT ERROR`、标准 Godot fatal、GDScript parse / load failure，或 JUnit 缺失、为空、不可解析、`tests <= 0`、`failures != 0`、`errors != 0` 时均 fail closed。不要绕过 Bridge 手工拼 GUT 的 Godot 命令，也不能仅凭进程退出码 0 判通过。

`headless-boot` 会在同一私有项目快照中先用 `--headless --editor` 完成资源导入与全局 `class_name` 扫描，再启动正式主场景；任一阶段出现脚本解析错误都会返回失败。这样新 clone 即使尚未生成 `.godot/global_script_class_cache.cfg`，验证结果也不会依赖本机编辑器缓存，多个只读 Bridge 任务也不会同时改写仓库 cache。

当前能力：

- `export-tree`：解析 `scenes/*.tscn`，输出场景节点树 JSON（不启动 Godot）。
- `validate-data`：调用 `tools/validate_data.py`。
- `godot-version`：调用本机 Godot 输出版本。
- `headless-boot`：运行 `godot --headless --path <project> --quit`。
- `gut`：在同一私有快照内阻塞完成 Godot import 后隔离运行固定 GUT CLI，默认覆盖 unit + integration，并以 fatal log 与 JUnit `tests / failures / errors` 双门禁判定结果。
- `test_godot_bridge.py`：不启动 Godot，校验 catalog 完整性、28 个旧 CLI 兼容、三类 runner 路由、逐命令 policy 透传、未知命令 fail closed、smoke / GUT 隔离环境、GUT import 顺序与失败短路、marker / 额外 ERROR、GUT exit-0 fatal 与 JUnit 缺失 / 空 / 失败门禁，以及项目参数改写、cache seed 白名单、manifest 重试、只读快照 / writer 独占路由和控制台编码降级。
- `runtime-smoke`：按 catalog 启动正式主场景的通用 test command，使用 open-warzone setup 断言 F4/F12 输入、池化、伤害、兴趣点和结算。
- `settings-smoke`：按 catalog 挂载 `client/tools/settings_smoke.gd`，断言 F7 设置持久化、范围校验、坏配置回退和语言设置联动。
- `gear-mod-smoke`：按 catalog 挂载 `client/tools/gear_mod_smoke.gd`，断言 F11 固定效果、无等级单份授予、重复实例逐份乘算、无等级 API 和替换式 modifier 幂等性。
- `save-smoke`：断言 Meta v4 / Run v19 roundtrip、GameplayEffectRuntime 与精确 `mod_environment` 恢复、`.bak` 回退、双坏档隔离、Meta v3→v4 迁移，以及旧 Run v18 保留原文件但拒绝继续；环境缺包、版本或 gameplay hash 不匹配同样保留拒绝，不按坏档隔离。
- `module-world-smoke`：按 catalog 的 gameplay setup 断言 F13 同 seed assignment / 内容敏感 hash、不同 seed 变化、坐标转换、起点威胁暂停 / combat gate、敌人出生倍率锁定、3×3 chunk 上限、离开 / 返回不重复生成、迷雾、意识核直接完成、Run v19 与效果程序恢复、坏 hash fail closed；同时覆盖刷怪笼周期 program 的计时、锁定计划、多实例与普通奖励链。
- `module-world-technical-slice-smoke`：经 `--module-world-technical-slice` opt-in 入口跑中心 3×3 首片，断言外圈 40 槽封锁及片内意识核直接完成 / 续局；回放验证使用 Replay v9，并明确保留但拒绝 Replay v8。
- `startup-probe`：仅在用户明确要求性能测试时，以 Bridge 的单调时钟测量正式主场景 `BOOT_BEGIN` 首帧到默认模块世界进入 `PLAYING` 的耗时，硬门槛为 2 秒；进程冷启动到 `BOOT_BEGIN` 只作诊断。该命令不属于日常回归或默认交付义务。

后续扩展：

- `--play-replay <file>`：headless 跑回放并输出帧 diff。
- `--validate-project`：完整项目落地后校验 autoload、Project Settings 和资源引用。

> 推荐：**项目早期先做自研 bridge**（成本低、可控），等 Godot MCP 生态成熟再换。

## 5. 元规则

- 只有长期、跨系统且高代价难回滚的引擎集成才新增 ADR；普通工具配置由本页或对应配置直接记录。
- AI agent 工作时**先确认当前是否启用了 MCP/Bridge**，避免重复造轮子。
