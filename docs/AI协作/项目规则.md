# 项目规则

> **权威范围**：本文件是所有 AI 平台共享的项目规则正文；平台规则文件只能提供加载适配，不能复制、改写或放宽这里的约束。

## 1. 开工与权威

- 开始任务先读 `AGENTS.md`、本文件、`docs/AI协作/快速开工.md`、`docs/AI记忆/current_state.json` 与 `docs/AI导航.md` 相关段落。
- 用户最后明确指令高于历史摘要、TODO 和当前状态；上下文压缩后重新以用户最后指令对齐。
- 需求、术语、验收标准或授权边界无法从仓库确认时，先问一个简短问题；只对低风险、可撤销细节作明示假设。
- 权威来源：玩法设计看 GDD；约定字符串看词表；测试政策看测试策略；公共代码契约看模块文档；重大决策看 ADR；当前优先级看 TODO。
- `docs/AI记忆/current_state.json` 只提供当前阶段导航，不记录完成历史、验证历史或隐式授权。

## 2. 引擎、目录与实现

- 正式客户端使用 **Godot 4.7.1 stable + 类型化 GDScript**；遵循 Godot 4.7 style guide 与项目更严格规则。
- 正式项目根为 `client/`；场景、脚本、数据、locale、模板与资产分别放在既有对应目录，不散落新文件。
- `output/test_lab` 仅用于快速 UI / 素材 / 交互实验；未经用户授权不得接入正式客户端。
- `draft/` / `DRAFT/` 是人工草稿禁区，除非用户在当前任务明确点名，否则不得读取、搜索、修改、整理、引用或提交。
- 优先小而精准的修改；不要借格式化、重构或规则升级批量改动无关代码。

## 3. 数据、文本与契约

- 可调数值必须在 `client/data/`；平表优先 CSV，复杂配置优先 JSON，通过 `DataLoader` 加载和校验。
- 新增或改变数据字段时，在 `client/data/README.md` 记录含义、单位、默认值、范围和调参影响。
- 玩家可见文本使用 locale key；`strings.csv` 同时提供 `zh_CN` 与 `en`，动态数值使用命名占位符，不在译文重复写死平衡数值。
- UI 尺寸以英文长度为最低基准；视觉、听觉、手感、色弱和真实设备结论只能由人工给出。
- 约定字符串只来自 `docs/词表与契约.md`；代码引用 `client/scripts/contracts/` 生成常量，禁止手改生成文件。
- 新 id 先登记词表，再运行 `tools/sync_contracts.py`；数据加载遇到未知 id、类型或范围错误应 fail fast 并给出文件与字段。

## 4. 运行时边界

- 输入：业务只消费 `InputService` 的归一化 intent 和生成 action 常量；只有 `InputService` 可直接访问 GUIDE，`InputMap` 仅限 GUIDE / UI bridge / 测试边界。
- 随机：玩法随机只走 `RNG.<stream>`；禁止裸 `randi` / `randf` 等 API。
- 时间：玩法时间只走 `GameClock`；禁止系统时间参与玩法判定。
- 流程：状态和暂停只由 `GameState` 管理；业务不得直接读写 `get_tree().paused` 或维护平行状态布尔量。
- UI：弹窗只走 `UIManager.push/pop/replace/clear`；业务不得直接把弹窗 `add_child` 到场景树。
- 高频实体：只走 `PoolManager.acquire/release`，并实现池重置契约。
- 伤害：只走 `Combat.apply_damage(target, DamageInfo)`；不得直接修改目标生命。
- 持续效果：使用 `StatusEffect` 与 `StatusEffectComponent`，显式声明叠加规则。
- 存档：只走 `SaveManager`，保留标准 envelope、原子写入、备份回退、损坏隔离和明确迁移 / 拒绝策略。
- 音频：只走 `AudioManager`；业务不得直接播放 `AudioStreamPlayer`。
- 本地 Mod：只走 `ModLoader + DataLoader` 声明式数据 patch；不得执行玩家脚本或扩展核心契约。
- 平台 / 在线：业务只走 `PlatformServices` / 规划中的 `OnlineServices`，不得直调 SDK 或在线 HTTP API。
- 埋点：事件名来自生成契约，通过 `Analytics` 统一上报，不收集敏感个人信息。

## 5. 内容与扩展

- Gear Mod、技能、道具和状态优先组合已登记的 capability / primitive / strategy，不按内容 id 写一次性分支。
- Gear Mod 与技能的通用效果程序由 `GameplayEffectRuntime`、Registry 与 Gateway 执行；新增原语必须同时提供 handler、参数校验和测试。
- 模式通过资源池、权重、tags、availability 与轻量覆盖组合内容，不复制整套资源或写 `if mode_id == ...` 内容分支。
- 保留 participant / team / Combat 边界，不把唯一玩家、唯一队伍或固定敌我关系写死进通用系统；当前不提前实现网络层。
- 内容可突破默认玩法限制，但不得突破 RNG、GameClock、Combat、UIManager、SaveManager、PoolManager 等工程边界。

## 6. 文档最小化

- 内部实现、私有 helper、文件拆分、测试新增和不改变行为 / API / 所有权 / 依赖的重构：**不更新文档**。
- 公共 API、signal、可观察行为、模块所有权或依赖边界变化：只更新对应 `docs/代码/<module_id>.md`。
- 玩家规则变化写 GDD；schema / 字段写数据或 locale 手册；约定字符串写词表；测试政策写测试策略；项目规则写本文件。
- 不为普通功能、bugfix、数值、内容、本地化、测试或内部实现建立 ADR。只有重大、长期、跨系统、协议断代、项目红线或高代价难回滚决策才写 ADR。
- 不维护人工 / 机器双索引、项目记忆、会话日志或一次性验证报告；完成和验证历史由 Git / PR / CI 保存。
- 新文档无需登记全局索引；只需放入正确目录、写清权威范围，并从真实入口建立必要链接。

## 7. 测试与人工验收

- 按 `docs/测试策略.md` 依据当前差异选择最低充分证据；不得沿用上一任务的验证矩阵。
- 修改正式 GDScript 至少跑对应 lint；schema、契约、存档、回放、autoload、性能敏感代码按测试策略追加专项验证。
- 黄金回放只有稳定行为或玩法指纹有意变化时才重录；bugfix 或内部重构默认只重跑。
- `perf-probe`、`startup-probe` 及其他性能采样只在用户当次明确要求时运行。
- 标为人工检查 / 人工验收 / L5 / 真实设备 / 视觉、听觉或手感验收的项目，AI 只能整理步骤与预期，不能执行或宣称通过。

## 8. 沟通、PowerShell 与 Git

- 面向用户默认使用中文。用户问风险或 review 时基于事实；未发现问题就明确说明，不硬找问题或过度优化。
- 新需求实施前简短说明价值、性价比、复杂度和主要风险；若与既定约束冲突，先说明并给替代方案。
- PowerShell 固定字符串搜索优先 `rg -F`，选项写在 `--` 前；路径使用 `-LiteralPath`；原生程序立即检查 `$LASTEXITCODE`；不混用 Bash / cmd 或 `Invoke-Expression`。
- 大型、可独立回滚的变更完成后默认提交；细微改动不自动提交。大型代码改动提交前执行事实型 review。
- 提交前检查 `git status --short`、任务相关 diff、`git log --oneline -10` 和相应验证；只 stage 本任务文件，不带入用户改动、草稿或本机配置。
- commit 使用 Conventional Commits，不使用 `--no-verify`，除非用户明确批准且提交信息说明原因。

## 9. 收尾自检

- 可调数值、玩家文本、输入、随机、时间、UI、伤害、存档、音频、对象池和平台调用是否仍走统一边界？
- 新 id 是否来自词表并完成生成同步？数据 / locale 是否通过校验？
- 是否只更新了直接权威文档，没有扩散到导航、状态或历史日志？
- 自动验证是否匹配当前风险？人工专属项是否仍标记待人工验收？
- 是否保护了用户已有改动并只提交本任务范围？
