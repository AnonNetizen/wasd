# 文档维护指南

> **权威范围**：本文件定义“什么变化需要改哪一份文档”；目标是单一权威和最小改动面。

## 1. 默认规则

- 文档记录稳定契约，不记录提交历史、验证流水账或私有实现清单。
- 先改直接权威来源；不要为了“同步”再复制到导航、TODO、当前状态或其他手册。
- Git / PR / CI 是完成历史和验证历史；仓库不维护项目记忆、会话日志或一次性报告。
- 新文档放入正确目录并从真实入口链接即可，不登记人工 / 机器索引。
- “AI 修改说明”不是必需模板；权威文档只需在标题后用一句话说明自身范围。

## 2. 最小改动矩阵

| 变化 | 默认文档改动 |
|------|--------------|
| 私有 helper、文件拆分、测试新增、无行为 / API / 所有权变化的重构 | 0 个 |
| 公共 API、signal、生命周期、可观察行为、模块所有权或依赖边界 | 对应模块文档 1 个 |
| 玩家规则、长期玩法设计 | `docs/游戏设计文档.md`；仅当模块公共契约也变时再改模块文档 |
| 数据 schema / 字段 | `client/data/README.md`；仅当加载器公共契约变时再改模块文档 |
| locale key、语言列、占位符规则 | `client/locale/README.md` |
| stat / effect / action / pool / status / audio / RNG 等约定 id | `docs/词表与契约.md` + 生成产物 |
| 测试层级、覆盖率、golden、性能或人工验收政策 | `docs/测试策略.md` |
| AI / Git / PowerShell / 人工验收等项目规则 | `docs/AI协作/项目规则.md` |
| 当前优先级或待决策项 | `docs/TODO.md`；只有阶段 / 入口改变才更新 current state |
| 新目录或新的顶层系统类别 | `docs/AI导航.md` |
| 重大长期决策 | `docs/决策记录.md` + 直接受影响的权威文档 |

修改 README、CONTRIBUTING、CI 或平台适配器时，只改真实入口或执行方式受影响的文件，不按平台数量复制共同规则。

## 3. ADR 门槛

只有以下决策写 ADR：

- 核心玩法方向。
- 跨系统架构、所有权或依赖边界。
- 存档、回放、数据协议断代。
- 项目级红线。
- 高代价、难回滚的工具链或工作流策略。
- 对既有重大 ADR 的实质取代。

普通功能、局部行为 / UI、bugfix、数值、内容、本地化、测试补强、文档澄清和内部实现不写 ADR；拿不准时默认不写。

## 4. 修改流程

1. 判断变化属于上表哪一行。
2. 读取并修改直接权威来源；内部实现变化可直接跳过文档。
3. 用 `rg -F` 检查旧名称、旧路径或旧版本残留。
4. 文档结构、路径、ADR、current state 或 `# Doc:` 变化时运行 `python tools/docs_health_check.py`。
5. 最终回复说明修改了哪个权威来源；无需文档时说明“公共契约未变”。

## 5. 写作要求

- 写当前契约，不复述代码或复制其他权威正文。
- 标题、路径和术语稳定；表格用于映射，段落用于原因。
- 模块测试段只写测试入口和选择条件，不枚举每个 case 或最近一次通过数字。
- 过期历史从当前树删除；需要追溯时使用 Git。
