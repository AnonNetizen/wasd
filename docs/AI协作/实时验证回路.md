# 实时验证回路（风险分层反馈）

> 业界 AI 协作工作流（Cursor / Aider / Continue 等）能力的核心：**先用目标校验快速知错，再用完整门禁收尾**。
> 本项目通过目标脚本 + pre-commit hook + watch 脚本，把 CI 的核心校验前置到本地，使 AI agent 在 commit 前就被打回；完整 Stage 1 hook 可能达到分钟级，不能把它误当成每次编辑后的即时反馈。
>
> 权威范围：本文档只维护标题所述主题的长期事实，不登记实现过程或完成历史。

---

## 1. 四层反馈

| 层级 | 反馈延迟 | 工具 | 检查内容 |
|------|---------|------|---------|
| **保存即检（毫秒~秒）** | 编辑器内 | `.editorconfig` + IDE lint 插件 + watch 脚本 | 缩进/换行/未类型化变量 |
| **目标快检（秒级）** | 改完目标文件 | `validate_data.py` 或目标 lint / smoke | 当前改动的最小直接证据 |
| **commit 前（秒~分钟）** | pre-commit hook | 见下表 | 完整 Stage 1：数据 schema / 词表契约 / 文档链接等 |
| **push 后（分钟级）** | CI workflow | `docs-check.yml` + `godot-runtime.yml` | 全量静态检查 + 固定引擎 boot / GUT / 隔离 L1 smoke |

理想情况：CI 是“防线兜底”，commit hook 是“最终本地拦截”，目标快检负责快速纠错，IDE 是“打字时提醒”。ADR #192 后不得因为目标快检已通过就跳过最终 hook，也不得因为最终 hook 会运行同一脚本而在成功后重复一轮完整独立门禁。

当前落地状态：`.github/workflows/docs-check.yml` 提供静态 CI 防线；`.github/workflows/godot-runtime.yml` 固定 Godot 4.7.1，串行跑正式 headless boot、通过 `python tools/godot_bridge.py --project client gut` 执行的隔离 GUT/JUnit，以及隔离的 `l1-smoke`、`effect-runtime-smoke`。GUT canonical runner 不信任退出码 0：还会拒绝 fatal / parse / load 日志并要求 JUnit `tests > 0 / failures = 0 / errors = 0`。仓库已提供 `.pre-commit-config.yaml`，本地安装后可在 commit 前跑 Stage 1 检查，追加不启动 Godot 的 Steamworks Lab toolchain 单元回归，并在模块相关路径变化时条件式运行只读 `module-bake-check`，同时对 staged 文件的 EOF 多空行做自动修复；GUT 与完整 boot 不进入日常 pre-commit。

## 2. pre-commit hook（已落地）

工具：[`pre-commit`](https://pre-commit.com/)（Python 框架，`.pre-commit-config.yaml` 配置）。

安装：

```powershell
pip install pre-commit
pre-commit install
```

手动运行：

```powershell
pre-commit run --all-files
```

如果当前机器没有安装 pre-commit，按下表的脚本逐个运行即可。

**框架阶段已配置的 hook**：

| hook | 脚本 | 作用 |
|------|------|------|
| `sync-contracts-check` | `tools/sync_contracts.py --check` | 解析 `词表与契约.md`，确认 `_contracts.json` 与 GDScript 常量未漂移 |
| `validate-data` | `tools/validate_data.py` | 校验 `client/data/*.json` / `client/data/*.csv`、locale CSV 中的 schema、词表 id 与 locale key |
| `test-data-loader-schema` | `tools/test_data_loader_schema.py` | 用独立临时数据副本和 validator 子进程断言 DataLoader-facing schema；默认最多 4 路并行，`--jobs 1` 保留串行诊断 |
| `lint-gdscript-rules` | `tools/lint_gdscript_rules.py [paths...]` | 第一档 GDScript 项目规则 lint：传路径只扫改动脚本，无参数 / linter / 契约权威变化全量扫描 |
| `lint-project-rules` | `tools/lint_project_rules.py` | 第二档项目规则 lint：数据字段手册覆盖、locale 双语、release preset 禁 debug/dev_tools |
| `test-project-rules-lint` | `tools/test_project_rules_lint.py` | 固定项目规则 lint 的坏样例，防止字段文档、双语和 release 检查退化 |
| `lint-semantic-rules` | `tools/lint_semantic_rules.py [paths...]` | 第三档非阻塞语义 advisory：路径模式只扫目标 GDScript，无参数全量；特殊 id 分支、autoload 绕过、类型签名、`# Doc:`、contract 常量引用风险等规则不变 |
| `test-semantic-rules-lint` | `tools/test_semantic_rules_lint.py` | 固定语义 advisory lint 的报警与不误报样例，防止 warning 规则退化或重新泛化 |
| `test-steamworks-lab-toolchain` | `tools/test_steamworks_lab_toolchain.py` | 固定 console 解析、独立用户环境、精确成功 / 错误标志、超时终止、动态端口、轻量临时副本和源码 `steam_appid.txt=4955670` 保护 |
| `module-bake-check` | `tools/godot_bridge.py --project client module-bake-check` | 仅相关路径变化时启动 Godot，无写入检查 JSON v3、tile catalog、审核 hash 与全部生成 TSCN 的规范指纹 |
| `docs-health-check` | `tools/docs_health_check.py` | 直接扫描存活文档，校验死链、ADR 顺序、`# Doc:`、模块引用、current-state v2、平台规则适配器和退役路径 |
| `staged-whitespace-check` | `tools/check_staged_whitespace.py` | 自动修复 staged 文件的 EOF 多空行，再对 staged diff 跑 whitespace 检查，排除 `draft/` / `DRAFT/`；其他 whitespace 错误仍失败 |

路径路由规则：日常 UI / GDScript 只触发增量两档 lint 与低成本完整性 hook；固定来源的 `client/addons/gut/` vendored GDScript 不进入项目风格 / 语义 lint，项目自有 `client/tests/**/*.gd` 仍正常扫描；DataLoader schema 回归只由 validator、DataLoader、schema 测试、difficulty profile 或契约权威变化触发；两套 lint 自测与 Steamworks 工具链自测只由各自实现 / 测试路径触发。CI 继续无参数全量运行全部脚本，作为路径遗漏的兜底。

**暂未配置的候选 hook**：

| hook | 原因 |
|------|------|
| `commitlint` | 仍按 `.gitmessage` 与 AI Git 策略执行；后续可加独立 commit-msg hook |
| `check-doc-links` / `check-numbering` / `check-version-sync` | 已由 `tools/docs_health_check.py` 覆盖主要检查，暂不拆脚本 |

**代码落地后追加**：

| hook | 脚本 | 作用 |
|------|------|------|
| `gdformat-check` | `gdformat --check` | GDScript 格式化 |
| `gdlint` | `gdlint` | GDScript 静态检查 |
| `validate-schema` | `ajv-cli` 或等价校验器 | 数据 CSV / JSON Schema 校验 |

## 4. AI agent 行为约定

- **agent 改完文件应自动跑 hook**：日常执行一次 `pre-commit run --files <本次文件>`；只有 hook / validator / linter 等门禁实现变化、大型全仓交付或发版前才执行一次 `pre-commit run --all-files`。没安装 pre-commit 时跑按同一路由选择的等价命令。
- **每次按当前任务重新分级**：不得沿用上一项大型任务、上一轮会话或 `current_state.json` 里的验证矩阵。简单已有字段调参先跑直接校验，只有当前改动命中测试策略中的更高层责任时才追加 L1~L4；L5 始终交给人工。
- **昂贵门禁去重**：推荐顺序是“快速目标校验 → 必要专项 → 一次最终 file-scoped hook”。若最终 pre-commit 已包含同一 schema / lint / docs health 门禁，不得在成功后无诊断目的地重复跑完整独立版本；独立重跑只用于定位失败或验证 hook 未覆盖的边界。
- **工作树与暂存区分开**：`staged-whitespace-check` 只读取暂存 diff；任务文件尚未暂存时，另跑一次 `git diff --check -- <本次文件>`，不能把该 hook 的 no-op 结果计作工作树已检查。
- **先确认覆盖，再跑回归**：运行或更新黄金回放前，先确认输入和稳定摘要确实覆盖本次变量。未覆盖玩家移速、且没有精确坐标样本的 replay 不能证明移速正确，也不得仅因时间戳、tick 或 hash 文本噪声重录基线。
- **Bridge 只读 Godot 命令可并行**：ADR #198 后，Bridge 默认把 boot / smoke / GUT / replay / check 等只读命令放进逐进程临时项目快照，并同时隔离 `.godot`、`APPDATA` / XDG / `HOME` 与测试结果。快照创建期间有短锁和 source manifest 前后校验；多个 child 在快照完成后可并行。`vfx-bake`、`module-bake`、`capture-golden-replay`、`capture-gear-mod-pickup` 会写回项目，Bridge 自动对原项目全程独占。裸 Godot 或绕过 Bridge 的 runner 仍不得并发。
- **GUT 只走 Bridge**：本地与 CI 都调用 `python tools/godot_bridge.py --project client gut`；默认 unit + integration，需要定位时重复传 `--test-dir`。Bridge 为每次运行隔离项目快照、`APPDATA` / XDG / `HOME` 与 JUnit，并校验 fatal log 与 JUnit，不手拼裸 Godot GUT 命令，也不接触真实 `user://` 或共享 `.godot`。
- **超时先收尾再重试**：Godot / Python bridge 超时后先核对命令行并终止本次启动的精确子进程树，再诊断缓存或重试；不得把仍在后台运行、被超时截断或只有部分日志的任务当作通过。
- **失败时自我纠错**：hook 输出格式约定为「文件 + 字段路径 + 期望值」，agent 据此直接定位修复。
- **不要绕过**：禁止使用 `--no-verify` 跳过 hook（除非明确告知用户原因）。
- **review 先看工具输出**：正式 review 按 `docs/AI协作/代码审核流程.md` 执行，先处理 lint/test/docs check，再让 LLM 重点读当前 diff。

## 5. 与 CI 的关系

- CI（`docs/CICD规划.md` 阶段 1）跑**全量 + 跨文件**校验，是最终防线。
- 静态 CI 跑 `tools/sync_contracts.py --check`、`tools/validate_data.py`、`tools/test_data_loader_schema.py`、两档阻塞 lint、语义 advisory 及其回归、`tools/docs_health_check.py` 与 whitespace diff；运行时 CI 另跑固定 Godot 版本、正式 headless boot、Bridge GUT/JUnit 与两条隔离 L1 smoke。commitlint、黄金回放、平衡 sim 和性能探针仍未加入常规 CI。
- pre-commit 对低成本完整性检查保持全量，对 schema 回归、增量 GDScript / semantic lint、lint 自测、Steamworks 工具链自测和 Godot `module-bake-check` 按路径触发；CI 仍对 Stage 1 无参数全量执行。
- 两者用同一份脚本（`tools/*.py`），CI 调用方式不同：
  - CI：`python tools/sync_contracts.py --check && python tools/validate_data.py && python tools/test_data_loader_schema.py && python tools/lint_gdscript_rules.py && python tools/lint_project_rules.py && python tools/lint_semantic_rules.py`
  - hook：`.pre-commit-config.yaml` 调用同一批脚本，并额外运行 staged whitespace check

## 7. 元规则

- hook 新增 / 调整必须同步本文件与 `docs/CICD规划.md`；只有改变项目级执行模型且难以回滚、达到 ADR 门槛时才新增 ADR，普通 hook 修正不建 ADR。
- hook 失败但用户需绕过时，必须在 commit message 写明原因（`chore: bypass <hook> due to <reason>`）。
